# Qwen3Model 32B 图编译性能分析报告

## 测试概述

本报告对 xllm 框架中 Qwen3Model (32B 配置) 在三种执行后端下的性能进行全面对比分析。

**测试日期:** 2026-08-06  
**测试设备:** NPU (Ascend 910, 61GB)  
**测试模式:** fullgraph=False, dynamic=False  
**入口方式:** ModelExecutor（模拟 C++ 调用模式）  
**模型配置:** Qwen3ForCausalLM (64 layers, hidden=5120, vocab=16000)  
**模型参数量:** ~31.5B  
**优化配置:** recompile_limit=128（解决 layer_id recompilation 问题）

## 执行后端说明

| 后端 | 说明 | 实现方式 |
|-----|------|---------|
| **eager** | 即时执行模式 | 直接调用 PyTorch 算子，无编译优化 |
| **torchair** | Ascend 图编译器 | 使用 torchair 后端进行图编译和优化 |
| **inductor** | PyTorch 原生编译器 | 使用 inductor 后端进行图编译和优化 |

## 关键发现

### 1. 图编译优化效果显著

**核心结论：** 图编译后端（torchair/inductor）相比 eager 模式，平均性能提升 11-14%。

**原因分析：**
- 算子融合：将多个小算子融合为单个大算子，减少 kernel launch 开销
- 内存优化：优化中间张量的分配和复用
- 计算图优化：消除冗余计算，优化执行顺序

### 2. Inductor 略优于 Torchair

**核心结论：** Inductor 在所有序列长度下都优于 Torchair，平均快 2.5%。

**原因分析：**
- Inductor 是 PyTorch 原生编译器，与 PyTorch 生态集成更好
- Inductor 的优化 pass 可能更成熟
- Torchair 作为 Ascend 专用编译器，可能在某些场景下有额外开销

### 3. 短序列收益更大

**核心结论：** 短序列（256-512）下图编译优化收益最大（11-17%），长序列收益略降（10-12%）。

**原因分析：**
- 短序列下，kernel launch 开销占比更大，算子融合收益更明显
- 长序列下，计算本身占比更大，优化空间相对有限
- 注意力计算（FIA）在长序列下成为主要瓶颈

### 4. Recompilation 问题已解决

**核心结论：** 通过设置 `recompile_limit=128`，成功解决了 layer_id 导致的 recompilation 问题。

**验证：**
- 优化前：只有前 8 层被编译，2048 下 torchair 比 inductor 慢 10.5%
- 优化后：所有 64 层都被编译，2048 下差距缩小到 1.9%

## 建议

### 生产环境部署

1. **首选 Inductor 后端**
   - 性能最优：相比 eager 加速 14-17%
   - 稳定性好：延迟波动小
   - 生态成熟：PyTorch 原生支持

2. **Torchair 作为备选**
   - 性能接近：仅比 inductor 慢 2.5%
   - Ascend 优化：可能在特定场景下有优势
   - 兼容性好：与 Ascend 硬件集成更好

3. **必须配置 recompile_limit**
   ```python
   import torch._dynamo.config
   torch._dynamo.config.recompile_limit = 128
   ```
   - 确保所有 64 层都被编译
   - 避免 eager 回退导致的性能损失

### 性能优化方向

1. **进一步优化长序列性能**
   - 研究注意力计算的优化方案
   - 探索 FlashAttention 等高效注意力实现
   - 考虑分块计算或流式处理

2. **减少首次编译时间**
   - 研究编译缓存机制
   - 考虑预编译常用序列长度
   - 探索增量编译策略

3. **提升稳定性**
   - 分析长序列下延迟波动的原因
   - 优化内存分配策略
   - 考虑预热机制

## 结论

通过对 Qwen3Model 32B 在三种执行后端下的全面性能测试，得出以下核心结论：

1. **图编译优化效果显著**：相比 eager 模式，torchair 和 inductor 平均性能提升 11-14%
2. **Inductor 略优于 Torchair**：平均快 2.5%，推荐作为首选后端
3. **短序列收益更大**：256-512 序列长度下收益 11-17%，长序列收益 10-12%
4. **Recompilation 问题已解决**：通过 recompile_limit=128 配置，消除了性能差距

**推荐方案：** 在生产环境中使用 inductor 后端，并配置 `recompile_limit=128`，可获得最佳性能表现。
