## 软硬件与依赖

| 项目 | 本次实际环境 |
|---|---|
| 硬件 | Atlas A3，Ascend910_9362，单个逻辑NPU |
| CANN | 9.1.0 |
| Python | 3.11.4 |
| PyTorch | 2.7.1+cpu（配合torch_npu运行NPU，并非CPU代算） |
| torch_npu | 2.7.1.post4 |
| triton-ascend | 3.2.1 |
| Triton API | 3.2.0 |
| NumPy | 1.26.4 |

已配置环境可直接执行下方命令。新建环境应先安装发布方提供的 A3/CANN 9.1.0 配套软件包，
不要使用 CUDA Triton 替代 triton-ascend。拿到配套离线 wheel 后可按以下形式安装：

```bash
python3 -m pip install /配套wheel目录/torch-2.7.1*.whl /配套wheel目录/torch_npu-2.7.1.post4*.whl
python3 -m pip install /配套wheel目录/triton-3.2.0*.whl /配套wheel目录/triton_ascend-3.2.1*.whl
python3 -m pip install 'numpy==1.26.4'
```

软件包需匹配机器的 aarch64、Python 3.11 和 CANN 9.1.0；上述为配套包安装方式，不代表通用PyPI可提供全部匹配包。
本次实例镜像（py3.11-a3-arm-20261106）预装 CANN 9.0.0 与上表 torch 配套栈；按任务书 3.1 另行安装社区版 CANN 9.1.0
toolkit 与 A3 算子包到同一 install-path，未更换驱动：

```bash
curl -O "https://ascend-repo.obs.cn-east-2.myhuaweicloud.com/CANN/CANN%209.1.0/Ascend-cann-toolkit_9.1.0_linux-aarch64.run"
curl -O "https://ascend-repo.obs.cn-east-2.myhuaweicloud.com/CANN/CANN%209.1.0/Ascend-cann-A3-ops_9.1.0_linux-aarch64.run"
chmod +x Ascend-cann-toolkit_9.1.0_linux-aarch64.run Ascend-cann-A3-ops_9.1.0_linux-aarch64.run
./Ascend-cann-toolkit_9.1.0_linux-aarch64.run --install --install-path=$HOME/Ascend/cann-9.1.0 --quiet
./Ascend-cann-A3-ops_9.1.0_linux-aarch64.run --install --install-path=$HOME/Ascend/cann-9.1.0 --quiet
```

社区版 9.1.0 将旧 `libhccl.so` 拆分改名（libhccl_v2/legacy 等），torch_npu 2.7.1.post4 仍按原名链接；
故在 `LD_LIBRARY_PATH` 末尾追加镜像自带 9.0.0 的 lib64，仅用于解析这一个库，其余计算库全部来自 9.1.0。
本题单逻辑 NPU，不涉及 HCCL 集合通信。toolkit 与算子包安装后的版本文件（version=9.1.0，
innerversion=V100R001C11SPC001B243）记录在 `environment.json`。

## 实际执行入口

```bash
source /home/developer/Ascend/cann-9.1.0/cann/set_env.sh
export LD_LIBRARY_PATH=/usr/local/Ascend/driver/lib64/common:/usr/local/Ascend/driver/lib64/driver:${LD_LIBRARY_PATH:-}:$HOME/Ascend/cann-9.0.0/lib64
export ASCEND_RT_VISIBLE_DEVICES=0
cd /工程所在目录
python3 run_guard.py
```

ASCEND_RT_VISIBLE_DEVICES 应按分配环境选择；本次容器暴露物理14/15，使用第一个可见逻辑设备0，且实际占用物理14。
本次实例独占该逻辑设备，无其他任务干扰。不要在其他机器照搬物理卡号。
无需 CMake、ACLNN 安装包或模型权重；prepare 调用 Triton 编译，首次编译不计入性能时间。
每次运行产生新的 `results/npu/<UTC时间>/`，失败返回非零并保留错误。

## 检查覆盖

- 14个规定正向输入：提交与原始NPU基线均精确等于独立CPU标杆；检查形状、类型、设备、连续性、输入不变和输出独立。
- 9个非法输入：prepare均抛出TypeError或ValueError。
- 额外检查合法输入值更新、调用时stream、非零storage_offset及同一Tensor存储重绑定，旧输出保持独立。
- 大小两组各在两条stream保留3份输出，逐份正确且互不别名。
- candidate/baseline各预热3次，记录单次活跃分配峰值、20次逐次调用与释放；全部释放后回到各自起点，残留0。

## 性能协议和结果

两侧各预热50次，交替6轮，每轮200次完整prepared.run，轮末设备同步。
包括Python提交、新输出和当次临时分配、设备计算与完成同步；排除输入准备、prepare和首次编译。
保留全部配对轮次，共同bootstrap重采样10000次，seed=20261031，分位数linear。

| flags_perf_small | 276.164452 | 49.123490 | 222.852407 | PASS |
| flags_perf_large | 494.323726 | 82.941690 | 405.883335 | PASS |

两组还均满足均值差>0、中位数差>0及提交均值≤85µs。
T=255/257两项补充均已完成6轮配对计时；任务书仅要求报告，不增加额外通过门槛。
