ASCEND_RT_VISIBLE_DEVICES 应按分配环境选择；本次容器暴露物理12/13，使用第一个可见逻辑设备0，且实际占用物理12。
本次命令还通过 `flock -n /tmp/cann-npu12.lock` 串行保护本测试。不要在其他机器照搬物理卡号或锁名。
无需 CMake、ACLNN 安装包或模型权重；prepare 调用 Triton 编译，首次编译不计入性能时间。
每次运行产生新的 `results/npu/<UTC时间>/`，失败返回非零并保留错误。

## 检查覆盖

- 14个规定正向输入：提交与原始NPU基线均精确等于独立CPU标杆；检查形状、类型、设备、连续性、输入不变和输出独立。
- 9个非法输入：prepare均抛出TypeError或ValueError。
- 额外检查合法输入值更新、调用时stream、非零storage_offset及同一Tensor存储重绑定，旧输出保持独立。
- 大小两组各在两条stream保留3份输出，逐份正确且互不别名。
- candidate/baseline各预热3次，记录单次活跃分配峰值、20次逐次调用与释放；全部释放后回到各自起点，残留0。

## 性能协议和结果

两侧各预热50次，交替6轮，每轮200次完整prepared.run，轮末设备同步。
包括Python提交、新输出和当次临时分配、设备计算与完成同步；排除输入准备、prepare和首次编译。
保留全部配对轮次，共同bootstrap重采样10000次，seed=20261031，分位数linear。

两组还均满足均值差>0、中位数差>0及提交均值≤85µs。
T=255/257两项补充均已完成6轮配对计时；任务书仅要求报告，不增加额外通过门槛。
