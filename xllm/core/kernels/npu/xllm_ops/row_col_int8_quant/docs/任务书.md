# 题目2-行列双向INT8量化算子开发任务书

## 1. 任务概述

对一个 FP16 矩阵同时输出按整行和整列绝对最大值量化的两份 INT8 矩阵，以及两组 FP32 绝对最大值。只覆盖稠密路径，不包含 threshold 或 COO 异常值输出。

功能对标：[天数智芯公开接口文档](https://developer.iluvatar.com/docs/ixformer#bnb_double_quant)。本题补充的 dtype、舍入、布局和边界约定以下文为准。2026-10-14 对公开 CANN 仓库文档及接口核验，未检出符合本题完整定义的融合接口；已有基础算子可以组合实现。正式立项由社区维护者复核。

## 2. 核心开发要求

### 2.1 功能实现要求

`r[i]=max_j(abs(x[i,j]))`，`c[j]=max_i(abs(x[i,j]))`。

非零统计量 s 对应的量化定义为 `int8(clip(rint(fp32(x*fp32(127/s))),-127,127))`；rint 使用最近偶数舍入。统计量为零时对应量化结果全零。输出统计量是绝对最大值，不是反量化 scale。qCol 的形状和行主序布局仍为 [M,N]。

### 2.2 算子工程模式

采用 **ACLNN 算子工程化开发**：提供 Ascend C 内核、OpDef 注册、shape/dtype 推导、tiling、可构建安装包、两阶段 ACLNN API 及独立 C++ 调用样例。安装在参与者自己的目录，不覆盖系统 CANN。

提供 `run(inputs, attributes) -> tuple[Tensor,...]` 的 PyTorch NPU 封装；**该正式入口必须调用本题 ACLNN API**。精度、性能和内存均验收这一入口。另提供 Kernel 直调入口用于交叉验证。计算和搬运在 NPU 完成，支持当前 stream，输入不变，输出为同一设备上的独立连续张量。

允许多阶段设备实现。框架入口校验输入个数、维度、dtype、连续性、尺寸及属性；C++ ACLNN 调用方负责提供有效设备指针、正确 ND 张量描述和不重叠输出。非法属性和未知属性必须报错。各接口说明见附件 README。

### 2.3 接口定义

| 参数 | 形状 | 类型 | 说明 |
|---|---|---|---|
| x | [M,N] | FP16 | ND 连续、有限值 |
| qRow、qCol | [M,N] | INT8 | 分别按整行、整列量化 |
| rowAbsmax | [M] | FP32 | 行绝对最大值 |
| colAbsmax | [N] | FP32 | 列绝对最大值 |

范围为 1≤M≤4096、2≤N≤4096，且 N 为偶数。输入为有限 FP16 值；不包含 NaN/Inf、稀疏异常值或反向。拒绝类型、维度、连续性及尺寸错误。输出范围固定为 [-127,127]。

## 3. 验收标准

### 3.1 软硬件环境要求

昇腾 910C（Atlas A3），实测型号 **Ascend910_9382**，单个逻辑设备，48 个 Vector Core、24 个 Cube Core。验收使用 CANN **9.1.0**、驱动 **25.5.t6.b001**、aarch64 openEuler 24.03 LTS-SP3、Python 3.12.13、PyTorch 2.10.0 与 torch_npu 2.10.0.post4+git5dd8ef3。完整依赖和镜像见 README。其他硬件/软件版本须重新验证，不据此承诺兼容。

### 3.2 精度要求

行列绝对最大值要求逐位一致。常规 INT8 要求逐元素一致；仅当 FP32 标杆量化前数值距半整数≤2e-5 时，允许相差 1，并记录涉及元素数。专门的精确中点及全零用例必须完全一致。不能全局采用±1 容差。

公开用例共 **27** 个，定义在 `case.json`。`golden.py` 为独立 CPU 标杆；`generate_data.py` 用固定种子生成输入。`verify.py` 可直接验证提交的 `run()` 入口。必须同时检查输出的 NPU 设备、形状、类型、连续性、独立存储和输入不变；不同起始指针但共享存储的输出同样不得通过。

### 3.3 性能要求

分别比较 FP32 Abs/ReduceMax/Round/Cast 组合，以及两次现有 DynamicQuant 加转置和独立 absmax 的组合。仅使用通过相同精度检查的实现，逐用例选择较快者。

采用相同输入、相同输出分配语义，预热 50 次，每轮 200 次，共 5 轮；取平均单次 API 至设备完成的墙钟耗时在各轮的中位数。输入传输及标杆比较不计入。记录设备事件时间作为补充，该时间包含提交间隙，不能称为 profiler 的纯内核时间。

逐用例要求 `提交实现耗时 / 同环境下较快的合法附件基线耗时 ≤ performance_baseline.json 中的上限`。每个性能用例的上限均不得大于 1：不得比同机较快的合法基线慢；原本小于 1 的加速要求继续保留。附表记录参考解答的真实耗时，仅用于校准；验收时重新测量双方，不能直接拿本表数值作跨机器比较。基线代码为 `baseline.py`。

### 3.4 内存要求

ACLNN 显式工作区上限为 `16 MiB + 4*ceil(M/64)*ceil(N/256)*(64+256)` 字节。16 MiB 是本环境 CANN 为核间同步保留的系统工作区，其余为行列局部统计；不得漏记这部分。不分配完整 FP32 矩阵或全矩阵转置作为自定义内核工作区。在输入已分配、运行时已预热的前提下，活跃张量分配峰值增量不超过输出字节数、上述工作区上限及 16 KiB 分配对齐余量之和。释放并同步后，重复 20 次调用的活跃张量分配须回到调用前水平。

内存口径是 PyTorch NPU 分配器的活跃张量字节数，含输出和工作区，不是整卡 HBM、驱动缓存或片上 UB。报告需说明片上缓冲设计。必须通过非法元数据拒绝、独立 stream、提前释放输入后跨 stream 分配压力及重复调用测试。

工程测试必须覆盖两个独立 stream、提前释放输入后另一 stream 的分配压力，以及直调和 ACLNN 各重复 20 次调用后的活跃张量回收。另用现有公开输入保留 8 次调用的全部输出，同时执行 32 次提前释放输出和同流分配写入压力；8 组输出必须保持独立且结果正确。重复调用不另计独立 case。

测试程序遇到任何未通过项目必须返回非零退出码，并保留错误日志；不得仅凭 JSON 中的总体状态替代用例覆盖、协议及阈值检查。


数量口径：本题有 **39 个有效输入用例**（27 个公开 + 12 个额外种子/存储偏移），另有 **13 个非法输入/属性场景**。非法场景在三个入口执行得到 39 条检查记录；额外输入在两个入口执行得到 24 条记录。性能与内存使用上述公开输入的子集，不重复计入有效输入总数；预热、计时迭代和重复调用也不算独立 case。

`coverage_requirements.json` 固定必须保留的用例 ID、公开输入定义指纹、入口组合、验证器反例及工程场景。验收必须逐项核对，不得以重复记录凑数；不得删除规定用例或将其标为跳过。可以在保留必测清单的基础上增加测试。
