# 行列双向INT8量化算子实现设计

2026-10-15 在 910C / Ascend910_9382 + CANN 9.1.0 完成重建和实机验收。公开精度 27 个、性能 5 个、内存 5 个均通过；详细要求和证据见[任务书](任务书.md)及[验收对照](验收对照.md)。

## 算法、分核与缓冲

输入为 FP16 矩阵，同时生成逐行和逐列量化的两份 INT8 输出，以及两组 FP32 absmax。只实现本题稠密路径，不含异常值 COO 输出。

直调路径有三个同 stream 顺序启动的内核：64×256 tile 局部统计、跨 tile 合并、32×256 tile 量化。正式 ACLNN 路径在一次设备启动中执行同样的三个阶段，两个阶段边界显式使用 SyncAll；先设置系统工作区，并用 GetUserWorkspace 获取用户缓冲。各阶段采用独立作用域复用片上资源。

设 R=ceil(M/64)、C=ceil(N/256)，局部统计占 4*R*C*(64+256) 字节。ACLNN 总工作区为 16 MiB + 上述局部统计，16 MiB 是该 CANN/SoC 的系统同步工作区。局部统计阶段片上缓冲 100864 字节，合并 2048 字节，量化 116864 字节；不生成完整 FP32 矩阵或全矩阵转置作为自定义工作区。

完整 tile 跳过无必要的清零，行量化后直接复用未修改的 FP16 片上 tile 计算列量化，减少一次 HBM 读取。零统计量安全处理；先 FP32→INT32 最近偶数舍入，再经过可精确表示 [-127,127] 整数的 FP32/FP16 转成 INT8，避免提前转 FP16 改变量化中点。行列 absmax 必须与独立 FP32 标杆逐位相同。

性能基线包括 FP32 abs/reduce/round/cast 组合，以及两次现有 DynamicQuant 加转置路径；只有通过同一输出与舍入检查的候选才计入基线。

## ACLNN 工程与框架封装

aclnn/ 基于 CANN 9.1.0 官方生成工程，包含 OpDef 注册、ND/dtype 声明、shape/dtype 推导、tiling 和 Ascend C 内核；目标 ascend910_93。tools/build_aclnn.py 在本工程专属英文暂存目录构建 .run 包，安装到本目录 aclnn_install/，不覆盖系统 CANN。

正式 run(inputs, attributes) 校验输入个数、设备、dtype、形状、连续性及属性，调用原生 PyTorch NPU 封装，最终执行本题生成的 GetWorkspaceSize 与 ACLNN 执行 API。每次调用分配独立连续输出，输入保持不变。两阶段 API 的独立 C++ 示例为 examples/run_aclnn_example.cpp。

前端取得当前 stream，保留输入的 stream 使用记录后提交回调；新输出及工作区在该 stream 分配，FIFO 执行顺序保证复用安全，不重复登记使回收延后的事件。回调只捕获地址、维度等元数据，不长期持有 Tensor。主机侧 ACLNN 准备和执行提交在队列回调中完成，使用 CANN 可用的临时内存池管理主机对象。量化工作区在调用线程按 16 MiB+局部统计的已验证预算分配；回调核对 GetWorkspaceSize 返回值不超出容量，仅使用原始地址。不能在队列回调内申请较大 NPU 工作区，否则可能等待自身队列。输入跨流使用由分配器记录保护，新分配输出及工作区由创建流的 FIFO 顺序保护。

不依赖镜像中未导出的 torch_npu 私有缓存辅助函数；主机临时池符号不可用时保留普通分配路径。该回退路径没有跨版本性能承诺，正式验收环境固定为本任务书版本。

## 直调交叉验证

run_direct() 提供原生框架直调；prepare() 返回保留输入、输出及工作区引用的预分配对象，随后调用提交内核。Prepared 对象不能被多条 stream 同时复用；每条 stream 应独立创建对象。

include/api.h 和 examples/run_example.cpp 提供 C ABI 与独立示例。C++ 调用方负责有效设备指针、正确张量描述和非重叠输出；框架入口承担元数据拒绝检查。直接入口的结果与正式 ACLNN 及独立 CPU 标杆交叉核对。

## 验收与复现

运行 verify_all.sh 重建 ACLNN 包、私有安装、构建框架扩展，再运行两个 C++ 示例、全部公开精度、独立公开验证器、扩展非法输入和偏移测试、stream/内存及性能，最后由 check_acceptance.py 按用例覆盖和逐项阈值检查。任一失败均返回非零退出。

本题实际完成 39 次非法输入检查、24 次额外种子/非零偏移检查及 3 项验收器反例测试；两条 stream、提前释放输入后跨 stream 分配压力、重复 20 次回收均通过。三个私有 ACLNN 包在同一进程交替调用 3 轮均通过。本轮另测 8 次保留输出、32 次提前释放输出和同流分配压力；缓存题另测连续两次追加。

性能双方均分配新输出；预热 50 次，每轮 200 次，5 轮取中位数。比较较快且精度合法的附件基线，所有耗时比上限均≤1，原本更严格的加速门槛保留。内存按预热后输入已存在时的 PyTorch 活跃张量峰值增量统计，包含输出和 ACLNN 工作区，允许 16 KiB 对齐余量；不是整卡 HBM。源码及生成产物与本次实际编译副本核对，指纹见 source_manifest.json。
