# 自验证步骤说明

## 环境

昇腾 Ascend910_9362，单个可见逻辑 NPU 0；CANN 9.1.0；Python 3.11.4；
PyTorch 2.7.1+cpu；torch_npu 2.7.1.post4；triton-ascend 3.2.1；NumPy 1.26.4。
实际设备、驱动、编译器及依赖版本见`task_submission/evidence/environment.json`。

## 构建与运行

将源码工程与结果目录分别放置。以下命令在 `dense_block_table/` 目录执行。
如 CANN 安装位置不同，只调整第一行路径；可见设备编号按机器分配设置。

```bash
source /home/developer/Ascend/ascend-toolkit/set_env.sh
export PATH="$HOME/.local/bin:$PATH"
export ASCEND_RT_VISIBLE_DEVICES=0
export MAX_JOBS=2
export TORCH_EXTENSIONS_DIR="$(dirname "$PWD")/extensions-reproduce"
python3 -m pip install --user ninja 'numpy>=1.22'
python3 collect_environment.py --output ../environment-reproduce.json
python3 native_loader.py
python3 verify.py --output-dir ../run-reproduce > ../run-reproduce.log 2>&1
```

结果目录和环境文件须不存在。完整入口返回 0 且 `result.json`、`functional.json`、
`generalization.json` 均为 PASS，才能确认本次规定检查通过。
只执行官方功能入口时可用：

```bash
python3 official/golden.py --verify-functional --implementation "$PWD" --output ../functional-only.json
```

## 覆盖与判定

- 14 个规定输入：候选与原始基线分别与独立 CPU 标杆逐元素比较，形状、dtype、
  NPU、连续布局、输入不变和输出独立均检查。
- 7 项非法输入：按任务书在首个性能输入上逐项构造，均抛出 TypeError 或 ValueError。
  原始官方验证器另在其内置字面值输入上执行同样 7 项检查。
- 两个主性能输入验证动态 X/M，大输入验证 INT32 输出上界；完整 run 入口另行核对。
- 双 stream 各保留 3 份候选输出和 3 份基线输出，每份均与 CPU 标杆一致且存储独立。
- 两个主输入测量一次完整 prepared.run 的活跃分配峰值；候选及基线重复 20 次释放后
  均回到测量前水平。
- 两组主性能、两组补充配对计时均预热 50 次、测量 6 轮、每轮 200 次。
  从完整调用开始至轮末设备同步结束，包含主机提交、新输出及临时分配、设备执行。
  prepare、输入生成和首次编译排除在计时之外。全部轮次保留。
- 两组主性能均须满足均值与中位数收益 > 0、配对 95% bootstrap 置信区间下界 > 0，
  候选均值分别不超过 75 μs / 60 μs。重采样 10000 次，seed=20261031，PCG64，线性分位数。
- 另以 B=4097 检查原生 Gather 分支的精度、非零 storage_offset、动态值和双 stream。

## 实测结果与复核位置

本次从最终源码包新建目录解压，使用独立 C++ 扩展构建目录运行全量验收。
环境、构建和验证的退出码均为 0。原始结果见 `task_submission/evidence/run-final/`，
构建及执行日志见 `task_submission/evidence/build.log` 和 `task_submission/evidence/verify.log`。
三个 Excel 报告从这些原始结果生成；性能表保留全部 24 个配对轮次。
每个轮次单次耗时可按 `elapsed_ns / 200 / 1000` 重新计算。

小输入均值 45.559827 μs，基线 103.502921 μs；大输入均值 45.254781 μs，基线 103.560132 μs。两组均通过全部主性能判据。
