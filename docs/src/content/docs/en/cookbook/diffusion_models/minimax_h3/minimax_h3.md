This guide serves MiniMax-H3 on Ascend NPUs with xLLM and generates video with
audio through `/v1/video/generation`. BF16 inference is validated with four
NPUs using TP2/SP2 and eight NPUs using TP2/SP4. The `fl2va` pipeline performs
text-to-video-and-audio (T2VA) when no image conditions are supplied.

## Environment

Prepare the Ascend development environment described in the
[Wan2.2 recipe](/en/cookbook/diffusion_models/wan/wan2_2/), then build from the
xLLM repository root:

```bash
git submodule update --init --recursive
python setup.py build --device npu
```

Before starting the service, load the Ascend environment and dependency library
paths. Install FFmpeg with both `ffmpeg` and `ffprobe` on `PATH`. If etcd is
enabled, also provide the Go toolchain required by
`third_party/Mooncake/mooncake-common/etcd/go.mod`.

## Checkpoint

Use the root Diffusers component layout from `MiniMaxAI/MiniMax-H3`.
The `_class_name` in `model_index.json` must be `MiniMaxH3ModularPipeline`;
keep all component directories declared in that index. Download the components
from the validated revision:

```bash
export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/data/models/.cache/huggingface
export MODEL_PATH=/data/models/MiniMax-H3

uvx --from huggingface_hub==1.33.0 hf download MiniMaxAI/MiniMax-H3 \
  --revision 42ed227ee7df40d41602854ae760620d6eb651fe \
  --local-dir "$MODEL_PATH" \
  --include model_index.json --include 'transformer/*' \
  --include 'transformer_ref/*' --include 'vae/*' --include 'audio_vae/*' \
  --include 'scheduler/*' --include 'audio_scheduler/*' --include 'processor/*' \
  --include 'text_encoder/*' --include 'tokenizer/*'
```

## Text conditioning

The H3 pipeline requires conditioning generated by the model's matching text
encoder. Supplying `input.prompt` alone does not run text encoding in this
service. Prepare `conditioning.pt` with these fields, using the same prompt
as the request:

| Field | Type and shape | Description |
| --- | --- | --- |
| `prompt` | String | Prompt used to produce the conditioning |
| `prompt_embed` | BF16 Tensor, `[1, L, 5120]` | H3 text features |
| `prompt_token_tags` | INT64 Tensor, `[L]` | Encoder token tags with values `0` or `1` |

Send the embedding with shape `[L, 5120]` in the HTTP request; the server adds
the batch dimension. Put the token tags in the tensor's
`parameters.prompt_token_tags.int64_tensor_param`. Random tensors, embeddings
from another model, or mismatched tags are not valid substitutes.

## Start the service

Start on four available NPUs. Set `XLLM_BINARY` to the built xLLM executable:

```bash
export ASCEND_RT_VISIBLE_DEVICES=0,1,2,3
export MODEL_PATH=/data/models/MiniMax-H3
export XLLM_BINARY=/path/to/xllm
export OMP_NUM_THREADS=8
export HCCL_BUFFSIZE=256

python -m xllm.launch_server serve --binary-path="$XLLM_BINARY" \
  --nnodes=4 --backend=dit --model="$MODEL_PATH" --model_id=minimax-h3 \
  --tp_size=2 --sp_size=2 --cfg_size=1 --vae_size=1 \
  --text_encoder_tp_size=1 --dit_h3_task_type=fl2va --dit_cache_policy=None \
  --dit_laser_attention_enabled=false --dit_sparse_attention_enabled=false \
  --master_node_addr=127.0.0.1:19885 --host=127.0.0.1 --port=8000 \
  --max_body_size=2147483648 --logtostderr=true
```

For eight NPUs, set `ASCEND_RT_VISIBLE_DEVICES=0,1,2,3,4,5,6,7` and change the
following arguments:

| Layout | `--nnodes` | `--tp_size` | `--sp_size` |
| --- | --- | --- | --- |
| Four NPUs | `4` | `2` | `2` |
| Eight NPUs | `8` | `2` | `4` |

`--max_body_size` allows for internal transfer of generated tensors; do not size
it based on the compressed MP4. The standard checkpoint has 56 attention heads,
96 video patch channels, and 32 audio channels. Parallel layouts must satisfy
`heads % (TP * SP) == 0`, `video_patch_dim % TP == 0`, and
`audio_in_channels % TP == 0`.

## Generate video and audio

Run this request from the directory containing `conditioning.pt`. The client
needs PyTorch to read the conditioning; HTTP and Base64 handling use the Python
standard library.

```bash
python - <<'PY'
import base64
import json
import urllib.request
from pathlib import Path

import torch

conditioning = torch.load("conditioning.pt", map_location="cpu", weights_only=True)
embedding = conditioning["prompt_embed"].squeeze(0).float().contiguous()
payload = {
    "model": "minimax-h3",
    "input": {
        "prompt": conditioning["prompt"],
        "prompt_embed": {
            "name": "prompt_embed",
            "datatype": "FP32",
            "shape": list(embedding.shape),
            "contents": {"fp32_contents": embedding.flatten().tolist()},
            "parameters": {"prompt_token_tags": {"int64_tensor_param": conditioning["prompt_token_tags"].tolist()}},
        },
    },
    "parameters": {
        "size": "1344*768",
        "num_inference_steps": 50,
        "seed": 42,
        "num_frames": 124,
        "fps": 24,
        "sampling_rate": 32000,
        "flow_shift": 12.0,
        "guidance_scale": 1.0,
        "num_videos_per_prompt": 1,
        "output_type": "base64",
    },
}
request = urllib.request.Request(
    "http://127.0.0.1:8000/v1/video/generation",
    data=json.dumps(payload).encode(),
    headers={"Content-Type": "application/json"},
)
with urllib.request.urlopen(request, timeout=3600) as response:
    result = json.load(response)
video = result["output"]["results"][0]["video"]["base64"]
Path("output.mp4").write_bytes(base64.b64decode(video, validate=True))
PY
```

`output.mp4` contains video and 32 kHz stereo audio. Inspect its media metadata:

```bash
ffprobe -v error -show_entries \
  stream=codec_type,width,height,nb_frames,r_frame_rate,sample_rate,channels \
  -of json output.mp4
```

The current service supports batch one and `num_videos_per_prompt=1`.
Resolution and frame count are aligned to model requirements; the resulting
duration must be between 5 and 15 seconds. The request above produces
1344×768 video with 124 frames at 24 FPS. Other tasks, checkpoint formats,
dtypes, and parallel layouts require separate validation.
